WHAT EXISTS
===========

✅ Document Storage
   ├── documents (metadata, versions, versioning)
   ├── document_texts (full extracted text)
   ├── embeddings (vector representations)
   └── document_versions (version history)

✅ Search & Retrieval
   ├── Keyword search (PostgreSQL full-text)
   ├── Vector search (pgvector cosine similarity)
   └── Hybrid search (BM25 + vector + RRF)

✅ Answer Generation
   ├── Query processing
   ├── Passage retrieval
   ├── LLM prompting (Ollama)
   └── Citation extraction

✅ Quality Features
   ├── Verification (Chain-of-Verification)
   ├── Citation confidence scoring
   ├── Hallucination detection
   └── Verification abstention

✅ Caching
   └── Redis answer cache (1-hour TTL)

✅ Multi-tenancy
   └── workspace_id for tenant isolation


WHAT DOESN'T EXIST
==================

❌ Conversation Management
   ├── No conversations table
   ├── No conversation_id field
   └── No conversation lifecycle

❌ Message Storage
   ├── No messages table
   ├── No message persistence
   └── No message indexing

❌ Session Tracking
   ├── No sessions table
   ├── No session_id field
   └── No session lifecycle

❌ Multi-Turn Support
   ├── No history loading
   ├── No context accumulation
   └── No conversation continuation

❌ Interaction Tracking
   ├── No user feedback storage
   ├── No question-answer pair history
   └── No interaction analytics

❌ Context Management
   ├── No conversation context table
   ├── No memory persistence
   └── No context accumulation

IMPORTANT CONSTRAINTS
====================

1. Context Window: 6000 tokens max
   - Currently: Document passages only
   - For multi-turn: passages + conversation history
   - This will reduce passage room if history included

2. LLM Model: Ollama qwen2:7b
   - Supports multi-turn in theory
   - Needs conversation structure in prompt

3. Caching Strategy:
   - Currently: Hash(query, document_ids, workspace_id)
   - For multi-turn: Would need Hash(..., conversation_id)

4. Performance Impact:
   - Loading conversation history = DB query overhead
   - Context assembly = token counting overhead
   - Message persistence = write latency
